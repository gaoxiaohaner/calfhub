架构原则：控制面与文件数据面分离；业务服务先采用模块化单体降低 3 人团队协作成本； 软件包使用对象存储承载；任务通过状态机和幂等机制保证“不会重复装、失败可追踪、重启可续跑”。
Web 管理端Vue 3 + TypeScript + Vite + ECharts开发效率高，适合仓库、终端、报表和配置型后台；组件化便于 AI 辅助生成与测试。
平台服务端Java 21 + Spring Boot 3，模块化单体成熟的鉴权、审计、事务、文件接口与企业交付生态；后续可按业务域拆分服务。
客户端C++17 + Qt，GUI / Agent 双进程适合 Windows 与国产 Linux 桌面；高权限 Agent 执行安装，GUI 仅负责交互，降低权限风险。
终端本地状态SQLite + 本地滚动日志保存任务状态、下载断点和执行记录，支持断网、重启、服务异常后的任务恢复。
数据与文件PostgreSQL + Redis + MinIO / S3业务状态、缓存锁与大文件制品职责分离，避免数据库存储安装包。
异步任务RabbitMQ；一期可按压力延后启用用于任务削峰、结果处理和仓库同步；小规模试点可先以内置任务表实现。
部署与观测Nginx + Docker + Prometheus + Grafana + Loki支持快速部署、应用多实例、指标监控、日志汇聚和问题追踪。

06 / INSTALL & ROLLBACK

安装、升级、回滚的统一执行模型

平台下发统一任务，客户端按操作系统和包格式选择执行器；统一状态、错误码和日志，避免“服务端成功、终端实际失败”。

统一状态机

任务全过程可追踪

待执行→ 环境检查→ 下载→ 哈希 / 签名校验→ 备份配置→ 安装 / 升级→ 结果验证→ 成功 / 待重启
执行失败→ 应用级回滚→ 回滚成功 或 回滚失败 + 严重告警
环境检查

安装前阻断不兼容任务

检查 OS、CPU、版本、磁盘、权限、依赖、冲突软件和运行进程，避免错误安装。

结果验证

不只依赖退出码

组合使用 MSI ProductCode、注册表、文件版本、包管理记录、服务、进程和自定义检测命令。

回滚分级

首期聚焦应用级回滚

保留旧包、备份配置、卸载新版本并恢复旧版本；系统快照和内核回退作为专项能力。

09 / RISK CONTROL

投标方案中需要主动说明的难点与控制措施

敢于明确边界、前置条件和验证方法，比承诺“所有系统全部支持”更能体现工程可信度。

国产 Linux 碎片化

措施：形成发行版 × 版本 × CPU × 桌面环境矩阵，首月完成真实硬件 PoC，按支持等级验收。

任意 EXE 无统一静默规范

措施：安装参数配置化；软件提供方必须提供静默参数、卸载命令和成功检测规则。

应用回滚无法保证绝对成功

措施：保留旧包和配置备份；提供自动尝试、回滚结果、严重告警和人工恢复流程。

3 人团队测试资源不足

措施：AI 生成测试用例 + 自动化回归；项目方提供真实终端池，验收阶段配置独立测试支持。

大文件和并发分发压力

措施：对象存储、分片、断点续传、限速、二级缓存节点，避免安装包进入数据库。

高权限 Agent 的安全风险

措施：GUI 与 Agent 分离、IPC 鉴权、任务签名、最小权限、完整审计、脚本能力分期开放。
